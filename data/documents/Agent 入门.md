# Agent 入门：从概念到第一个可用智能体

Agent（智能体）是能够自主感知环境、调用工具、围绕目标采取多步行动来完成任务的一类程序。它与"一次问答"的模型最大的区别，在于多了一个循环：规划 → 调用工具 → 观察结果 → 再规划。

## 1. Agent 是什么

Agent 指具备目标、工具和行动能力的智能体。判断一个系统是不是 Agent，看三点：

- 能不能拆解目标，而不是一次性给答案
- 能不能调用外部工具（搜索、数据库、代码执行）
- 能不能根据工具返回的结果，调整下一步动作

只满足"对话"的系统不是 Agent；满足"多步行动 + 工具反馈"的才是。

## 2. 核心组成

| 组件 | 作用 |
|---|---|
| 规划（Planning） | 把目标拆成可执行的步骤 |
| 工具（Tools） | 让 Agent 能查询、计算、写入外部系统 |
| 记忆（Memory） | 保存中间结论，避免重复劳动 |
| 执行循环（Loop） | 思考—行动—观察，直到任务完成或达到步数上限 |

## 3. 学习路径：先学什么，再学什么

**第一阶段 · 模型基础**
理解提示词、上下文窗口、结构化输出（JSON 模式）。目标：能让模型稳定输出固定格式。

**第二阶段 · 工具调用**
理解 function calling：如何声明工具、模型如何选择工具、参数如何校验。目标：能接一个真实工具（如搜索或数据库查询）。

**第三阶段 · 单 Agent 循环**
理解 ReAct（思考—行动—观察）。目标：能跑通一个"能查资料并回答"的最小 Agent。

**第四阶段 · 任务拆解与多 Agent**
理解什么时候需要拆成多个角色、角色之间如何传递信息。注意：这一步最容易过度设计，单 Agent 能解决时不要上多 Agent。

**第五阶段 · 评测与成本**
定义成功率、平均步数、时延、单次成本。目标：能量化"改了之后是否更好"。

## 4. 每个阶段练什么

1. 阶段一练习：让模型把一段自然语言需求转成 JSON，检查 10 次里格式正确几次
2. 阶段二练习：接一个查天气或查单词的工具，验证参数错误时的兜底
3. 阶段三练习：做一个"先搜索再总结"的最小 Agent，限制最多 5 步
4. 阶段四练习：把上面的 Agent 拆成"检索者 + 写作"两个角色，比较效果与成本
5. 阶段五练习：准备 20 条测试问题，统计成功率与失败类型

## 5. 常见误区

- **一上来做多 Agent**：单 Agent 循环都没跑通，拆角色只会放大混乱
- **只堆工具不做评测**：工具越多，失败点越多，没有评测就不知道坏在哪
- **把提示词当成 Agent 全部**：Agent 的难点在工具边界与失败重试，不在措辞
- **忽略成本**：多步循环的 token 消耗是单轮问答的数倍，不估算就无法落地

## 6. 怎么判断自己学会了

能清楚回答下面四个问题，就算入门：

1. 这个任务为什么需要 Agent，而不是一次问答？
2. 工具调用失败时，重试策略是什么？
3. 跑完一次任务平均要几步、花多少钱？
4. 失败案例里，占比最高的是哪一类（提示词 / 工具 / 模型能力）？

## 7. 与本项目的关系

本项目的问答与计划模块属于"单 Agent + 工具"形态：问答负责检索与生成，计划模块负责把目标拆成周任务。后续若要支持更复杂的任务，可先在这一层做步数上限与失败重试，而不是直接引入多 Agent。
